# 智能报告设计约定

## 时间窗口

智能报告每次生成只读取当前执行窗口内抓取入库的来源文章。

- 手动“立即生成”：窗口为点击触发时刻减去配置间隔，到点击触发时刻。
- 定时执行：窗口为 worker 定时触发时刻减去配置间隔，到 worker 定时触发时刻。
- 配置为 1 小时、4 小时、8 小时时，分别只回看对应时长。

`ai_digest_configs.last_window_end_at` 只用于判断某个智能报告源是否到达定时触发条件，不作为下一次生成窗口的开始时间。这样可以避免 worker 停止、任务失败或长时间未运行后，一次生成抓取过长历史范围。

候选文章窗口当前按 `articles.fetched_at` 判断，表示“这段时间内被 FeedFuse 抓取入库的文章”。如果来源 RSS 在当前窗口内才返回一篇发布时间较早的文章，该文章仍可能进入候选。

同一个智能报告源同一时间只允许一个 `queued` 或 `running` run。手动立即生成遇到已有运行中的 run 时复用该 run；定时执行遇到已有运行中的 run 时跳过本次投递，避免生成重复报告或让私人 FM 跟错生成批次。

前端进入某个智能报告源时，会通过后端查询该源是否存在活跃 run。若存在 `queued` 或 `running` run，列表页必须恢复生成状态并继续轮询 run 状态，避免用户切换 tab 或组件重新挂载后看不到“生成中”而重复点击“立即生成”。
