# Changelog

## [Unreleased]

### 新增

- 规划早班私人 FM：智能报告源可选生成口播稿与 StepFun TTS 音频，音频挂载在智能报告文章下播放。
- 增强智能报告生成体验：列表内展示持久生成状态，并在报告成功后继续跟踪私人 FM 状态。
- 私人 FM 增加“口播稿已生成”中间状态，便于区分口播稿生成和 TTS 音频生成阶段。
- 私人 FM 生成完成后合并 TTS 分片为单条完整音频，文章页优先使用完整音频播放器。

### 修复

- 修复智能报告生成窗口计算：立即生成和定时执行都按当前执行时刻回看配置间隔，避免抓取到过旧新闻。
- 修复智能报告立即生成与定时执行并发时可能创建重复 run，导致生成两份报告或私人 FM 对应批次混乱的问题。
- 修复智能报告切换 tab 后丢失生成中状态的问题，重新进入报告源会从后端恢复活跃 run 并禁用重复生成。
- 新建智能报告的首次生成窗口改为回看一个配置间隔，避免创建后立即生成时漏掉刚抓取的来源文章。
- 将智能报告文章内的私人 FM 模块移动到标题下方，避免播放器被长正文压到末尾。
- 私人 FM 重试默认复用已有口播稿，仅成功后的“重新生成”会清空旧稿并重新生成。
- 修复私人 FM 重试被队列 singleton 拦截后永久显示生成中的问题，并为超时 pending 状态提供重试入口。
- 收紧私人 FM 异步状态机：失败重试增加短冷却、后端限制 regenerate 使用场景、worker 跳过旧 job，并为 StepFun TTS 请求增加超时。
- 调整私人 FM 口播稿提示词，默认生成 1800-2600 个中文字符的完整早班 FM，而不是简短快讯。
- 私人 FM TTS 失败时保留 StepFun HTTP 状态码和响应摘要，避免页面只显示泛化的“稍后重试”。
- 修复 Docker 镜像中私人 FM 媒体目录未预授权给运行用户，导致音频写入失败的问题。
- 修正私人 FM 重试状态文案：已有口播稿时显示正在生成音频，而不是误提示正在生成口播稿。
- 修复智能报告 run 状态查询中 `feed_id` 字段未限定表名导致轮询接口返回 500 的问题。
- 修正 Docker healthcheck 使用容器内部 `127.0.0.1` 导致 web 服务误判为 unhealthy 的问题。
