# 项目并行协作约定

本文件是所有 Superwork 写入任务的协作入口，可补充本项目的公共模块归属。任务公告保存在 `parallel/<id>.json`，只记录当前影响；完成结果和验证证据保留在原有计划中。

## 读取与登记

- 开始任务时读取上下文中的 `parallel` 摘要；只读分析不创建登记。
- 准备写入前读取本文件，声明明确的文件或目录范围及公共影响，使用唯一任务标识与执行者标识登记。
- 同一任务跨技能交接复用 `id`、`owner` 和计划路径，不重复创建登记；新会话恢复时只有明确接续了原执行者身份才能更新旧记录，不能根据相同目标或时间推断归属。
- 登记后重新读取公告板。扩大范围、修改公共部分、恢复暂停任务以及最终检查需要修改文件时，再检查最新登记。
- 先读任务摘要；只有存在相关影响或归属不明时，才打开对方计划和对应规范，不批量读取所有计划。

## 影响判断

| 情况 | 行动 |
| --- | --- |
| 文件、接口和运行资源互不影响，或只读取稳定公共代码 | 继续执行 |
| 写入同一文件，或文件位于对方声明的目录范围内 | 先确认单一修改归属；未明确前暂停交叉部分 |
| 依赖对方正在修改的接口、类型、数据库结构、依赖版本或测试资源 | 继续独立部分，暂停依赖部分并记录原因 |
| 公共改动已经完成 | 重新读取实际实现与对方计划，确认契约和验证后继续 |
| 登记损坏、无法读取、归属或兼容性不明 | 保留记录，说明未知影响；无法排除影响的写入先暂停 |

文件路径不同不代表语义独立。公共改动由一个任务负责；后来者优先避让已有声明，登记后同时发现交叉的任务先暂停交叉写入，明确归属后再继续。协作登记也不能作为覆盖他人现有改动的依据。

## 更新与清理

- 每份 JSON 只由其 `owner` 更新；范围和公共影响变化时及时更新。
- `running` 表示任务仍在执行；仍有独立部分时继续并在计划中记录阻塞部分，无可继续的独立部分时更新为 `paused` 并填写 `reason`。记录不因时间久自动失效，暂停也不自动释放修改归属。
- 暂停原因和仍可执行的独立部分写入自身计划；不要让其他任务等待一项本任务其实尚未完成的公共变更。
- 最终验证与必要的计划交接完成后，只删除自己的任务记录，保留本文件、其他记录和历史计划。
- 中断、失败或检查未通过时保留记录，恢复前重新检查；只读验收不替其他任务清理登记。

## 记录字段与范围

记录包含 `id`、`owner`、`goal`、`status`、`writePaths`、`sharedImpact`、`plan`、`reason`、`updatedAt`。`writePaths` 使用项目相对的明确文件或目录，不使用通配符；无公共影响时用空数组，无计划时用 `null`。目录包含其下所有文件。

登记属于本地临时状态，不提交到 Git。此约定面向共享同一项目目录的 AI 会话，辅助它们判断和避让；不是文件锁，也不会自动暂停进程。不同 clone 或 worktree 的登记不自动共享。
