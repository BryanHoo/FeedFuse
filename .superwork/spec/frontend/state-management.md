# 前端状态管理

## 状态归属

- 短生命周期 UI 状态留在组件或 feature Hook
- 跨组件阅读器状态使用 `src/store/appStore.ts`，设置与认证分别使用 `settingsStore.ts`、`authStore.ts`
- 服务端数据通过 `src/lib/api/apiClient.ts` 读取，写入成功后以服务端响应校正本地状态
- 轮询与流式任务必须区分 pending、running、completed、failed 与 cancelled

## 阅读与收藏写入

- 单篇已读和收藏允许即时更新界面；同一文章的写入必须串行，不同文章可独立执行。
- 连续操作只接受最新意图的界面反馈；旧请求可以更新已确认值，但不能覆盖后续点击。最新写入失败时，仅恢复目标字段到最近一次成功状态。
- 未读数失败恢复只撤销本次实际扣减量，不能覆盖其他文章的计数变化；批量已读成功后再更新文章状态与统计。
- 可见列表、详情缓存和所有视图快照须同步已读与收藏字段，更新或回滚时保留正文等无关字段。
- 快照读取须等待文章写入结束；请求期间发生操作的快照须丢弃并重新读取，分页也遵循此规则。详情刷新允许更新正文，但不能以旧响应覆盖较新的已读或收藏状态。
- 自动已读按打开的文章触发，失败回滚、收藏和正文刷新不能重新提交或重置阅读计时；重新打开文章或手动标记允许重试。
- `src/test/store/appStore.test.ts` 覆盖失败重试、连续收藏、跨视图缓存、旧快照与详情响应、并发未读计数以及单篇与批量已读交叠。

## 设置自动保存

- 设置和密钥保存必须串行执行；排队任务开始时读取最新草稿，保存失败不能阻断后续任务
- 保存响应只能重建未发生新编辑的草稿；请求期间的新设置、密钥输入、删除意图和 RSS 校验状态必须保留
- 关闭或重新加载草稿后，旧响应不得重新创建或覆盖当前草稿，旧队列任务不得保存新编辑会话
- 自动保存状态只接受当前编辑版本的结果，过期响应和卸载后的响应不得修改状态；回归测试覆盖延迟响应、连续编辑、失败重试和关闭后重新打开

## 用户隔离

- 用户级 localStorage key 必须包含 `userId`，不能让后登录用户继承前一用户状态
- 获取当前用户后重新加载对应命名空间的设置与阅读器状态
- 登出时清理内存中的用户状态；持久化状态只按当前用户命名空间读取
- 具体 key 和兼容语义以 [长期交互契约](./contracts.md) 为准
